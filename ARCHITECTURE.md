# Архитектура ext-ic (Image Converter) — v1.1.0

## Слои

```
 popup.html / sidepanel.html / popup.html?view=tab
            │
        ui/main.ts ── собирает зависимости (DI) ──┐
            │                                      │
        ui/app.ts  (App: состояние вида, действия) │
            │  views/*: queue, settings-page,      │
            │  presets, log, crop, modal, …        │
            ▼                                      ▼
  core/*  (чистые функции)          platform/*  (побочные эффекты)
  command   — argv ImageMagick       converter    — маршрутизация задач
  capabilities — форматы, сигнатуры  engine       — wasm-imagemagick + таймаут
  settings  — схема, миграция v1.0   browser-codecs — canvas encode/decode
  filenames, zip, crop, presets,     queue-db     — IndexedDB
  log, formats, optim                settings-store — chrome.storage.local
                                     downloads, panels, pending-image
 background/index.ts — контекстное меню; конвертации там нет
```

Правило зависимостей: `core` ничего не импортирует из `platform`/`ui` и не трогает DOM/`chrome.*`.
`App` получает все сервисы через `AppDeps`, поэтому целиком тестируется в jsdom с фейками.

## Ключевые решения

**Движок не бандлится.** `magickApi.js` ищет `magick.js`/`magick.wasm` по собственному URL из
стектрейса. Если Vite вклеит его в чанк, воркер не найдётся. Поэтому файлы лежат в `public/lib/`,
импорт помечен внешним (плагин `ic-vendor-external` в `vite.config.ts`), типы — в
`src/lib/wasm-imagemagick/magickApi.d.ts`.

**Гибридный конвертер** (`platform/converter.ts`). При старте выполняется `convert -list format`,
и список форматов в UI строится по факту. Если ImageMagick не умеет писать формат, а браузер
умеет (WEBP), цепочка такая: IM (поворот по EXIF, обрезка, ресайз) → PNG → canvas-кодировщик.
Если IM не читает вход (WEBP, AVIF), браузер декодирует его в PNG и IM пробует ещё раз.
Каждый результат проверяется по сигнатуре: файл с чужим содержимым никогда не сохраняется.

**Таймаут и перезапуск.** Библиотека никогда не отклоняет промис, если воркер упал (OOM) — он
просто висит. `MagickEngine` ставит таймаут (180 с), задачи идут строго по очереди. По таймауту
модуль импортируется заново с `?gen=N` — это новый экземпляр модуля, значит и новый воркер.

**Жест пользователя.** `sidePanel.open()` (Chrome) и `sidebarAction.open()` (Firefox) работают
только синхронно внутри обработчика клика. Поэтому id окна кэшируется заранее, а в фоне панель
открывается до записи в storage.

**Синхронизация видов.** Настройки — `chrome.storage.local` (ключи `ic_*`, совместимы с v1.0) +
`storage.onChanged`. Очередь — IndexedDB (бинарники) + `BroadcastChannel('ic-queue')`. При
перечитывании сохраняется локальное состояние UI (раскрытые панели, превью) и элементы,
которые этот вид конвертирует прямо сейчас.

**Два таргета** из одного `src/manifest.ts`: Chrome — service worker + `side_panel`;
Firefox — `background.scripts` + `sidebar_action`, без разрешения `sidePanel`, Firefox 140+
(нужно для `data_collection_permissions: none`).

## Что было исправлено при переносе (v1.0 → v1.1)

| Проблема в v1.0 | Последствие | Исправление |
|---|---|---|
| AVIF, HEIC, HEIF, JP2, JXL, EXR, XWD «конвертировались», но внутри был PNG | пользователь получал `photo.avif`, который на деле PNG | список форматов по `-list format` + проверка сигнатуры |
| WEBP требует внешний `cwebp`, которого нет в wasm | WEBP не работал вовсе | WEBP через canvas-кодировщик браузера; lossless — где он честный (VP8L) |
| Входные WEBP/AVIF не читались | ошибка «no decode delegate» | фолбэк: декодирование браузером |
| `background.service_worker` в Firefox | расширение не запускалось в Firefox | отдельный манифест: `background.scripts` |
| `await storage.set()` перед `sidePanel.open()` | «Конвертировать» из контекстного меню не открывало панель в Chrome | открытие синхронно, до записи |
| Нет host-permissions | картинки с CDN без CORS молча не загружались | `optional_host_permissions` + кнопка «Разрешить и повторить» для конкретного сайта |
| Открытая панель не реагировала на контекстное меню | срабатывало только при открытии | подписка на `storage.onChanged` |
| ZIP без UTF-8-флага | кириллические имена в архиве ломались в Проводнике | флаг bit 11 |
| Ресайз по умолчанию не сохранялся | сбрасывался при каждом открытии | ключ `ic_resize`, профиль — `ic_profile` |
| Порядок очереди по строковому id (`f1, f10, f2`) | очередь перемешивалась после переоткрытия | `addedAt` + числовая сортировка старых записей |
| В режиме вкладки уход на другую вкладку удалял готовые файлы из БД | «пропадали» результаты | очистка только для popup/side panel |
| `window.confirm()` при удалении пресета | в popup/сайдбаре Firefox не работает | своё модальное окно |
| Перетаскивание рамки обрезки у края уменьшало её | неудобно | рамка сдвигается, размер сохраняется |
| Утечка blob-URL при синхронизации видов | память росла | превью переиспользуются, лишние URL освобождаются |
| Из stderr бралась первая строка — предупреждение `delegates.xml` | непонятные ошибки | берётся строка `@ error/` |
| Папка сохранения не проверялась (`..`, `:`, `CON`) | падение `downloads.download` → сохранение мимо папки | `sanitizeFolder` |
| Мёртвый код: `lib/zip.js`, `lib/fsHandle.js` (от Media Grabber), `ic-broadcast` в фоне, `clipboardRead`, `web_accessible_resources: lib/* для <all_urls>` | лишние права и поверхность атаки | удалено |

## Тесты

- `tests/unit` (Vitest + jsdom, 92 теста): command, capabilities, settings (включая миграцию v1.0),
  filenames, zip (собственный парсер архива), crop, presets/log/i18n, IndexedDB (fake-indexeddb),
  движок (таймаут, перезапуск, stderr), конвертер (маршруты, фолбэк, сигнатуры), контекстное меню,
  UI-контроллер на реальной разметке `popup.html`.
- `tests/e2e/convert.e2e.mjs` (Playwright + реальный `magick.wasm` в Chromium): PNG→JPG, PNG→WEBP
  с ресайзом, вход WEBP, обрезка, AVIF → понятная ошибка, битый файл, ZIP с кириллицей,
  сохранение настроек после перезагрузки.
- `addons-linter` для Firefox-сборки: 0 ошибок; 2 ожидаемых предупреждения (динамический `import()`
  для перезапуска воркера; ключ `data_collection_permissions` на Firefox для Android — Android не
  целевая платформа, там нет боковой панели).

## Предложения по архитектуре (по убыванию пользы)

### 1. Перейти на `@imagemagick/magick-wasm` — главное

Текущий движок — ImageMagick 7.0.8-28 от 2019 года, только делегаты jpeg/png/tiff/zlib.
Проверено на `@imagemagick/magick-wasm@0.0.44` (ImageMagick 7.1.2-32, сентябрь 2026):
нативно **пишет WEBP, AVIF, JXL, JP2, EXR, QOI**, **читает HEIC и RAW (DNG и др.)**, есть **lcms**
(корректные ICC-профили). Плата: wasm 15,4 МБ вместо 4 МБ; API объектный, а не CLI —
`buildConvertCommand` превратится в набор вызовов `image.autoOrient()/crop()/resize()/write()`.
Слой `Converter` уже это изолирует: нужен `MagickWasmEngine` в собственном Worker; UI и тесты
UI не меняются. Canvas-путь для WEBP останется фолбэком.

### 2. Конвертация вне popup

Popup уничтожается при потере фокуса — пакет из 50 файлов обрывается. Вынести очередь в
offscreen document (Chrome, `chrome.offscreen`) / фоновую страницу (Firefox, в ней есть DOM),
а UI оставить «тонким» клиентом по `runtime.Port`. Заодно решится п. 3.

### 3. «Спрашивать, куда сохранить» из popup

Диалог «Сохранить как» отбирает фокус → popup закрывается → blob-URL умирает вместе с ним.
Сейчас обходится открытием в боковой панели или вкладке. Правильно — отдавать скачивание
документу из п. 2.

### 4. Метаданные и цвет

`-strip` удаляет и EXIF, и ICC. Для фото в Display P3/Adobe RGB это сдвиг цветов.
Предлагается: перед `-strip` переводить в sRGB (`-profile sRGB.icc` — нужен lcms, см. п. 1),
и включить уже существующую в i18n, но неиспользуемую опцию «Сохранять метаданные».

### 5. Отмена и параллельность

Кнопка «Отменить» требует своего Worker вокруг движка (у текущей библиотеки воркер не наружу).
Там же — пул из `min(2, hardwareConcurrency/2)` воркеров для пакетов, с ограничением по памяти.

### 6. Анимация

GIF → WEBP через canvas даёт первый кадр. С п. 1 анимированный WEBP пишется нативно.

### 7. Хранилище

Очередь хранит оригинал + результат в IndexedDB. Для больших пакетов стоит проверять
`navigator.storage.estimate()` и не хранить результат после успешного сохранения (только метаданные
для журнала).

### Не советую

- Тащить React/Preact ради UI такого размера: `ui/dom.ts` (`h()`) + представления-функции
  читаются нормально и тестируются без фреймворка. Пересмотреть, если появятся сложные формы.
- Переводить UI-строки на `chrome.i18n`: он не умеет переключать язык внутри приложения, а это
  уже есть в настройках.
